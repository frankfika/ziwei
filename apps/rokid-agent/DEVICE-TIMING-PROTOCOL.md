# 真机手势时序测量协议（戴眼镜照着做，10 分钟出结论）

> **为什么有这份东西**：模拟器把「物理手势 → 宿主投递的键值与时序」整条链写死成了常量
> （双击 120ms、补发 Enter 600ms、方向键 60ms），所以它**永远只测一个最优点**，
> 假设错了测试照样全绿。商店那次驳回（「arrow 滑动事件问题 无法切换 请检查 global hook 相关」）
> 就发生在这层 —— 模拟器根本碰不到。
>
> `scripts/test-device-timing-contract.mjs` 用真代码把真机时序当变量扫了一遍，
> 结论是：**6 条时序里只要有 1 条越界，界面就会以特定方式坏掉**（表在下面）。
> 这份协议的作用就是把「越界会不会发生」从猜测变成**一次测量**。

## 1. 五条时序约束（**这是唯一的判定标准**）

| # | 约束 | 代码里的窗口 | 越界后的**确切症状** | 怎么测 |
|---|---|---|---|---|
| **C0** | **宿主必须为单击补发 `Enter`** | 路由只把 `GlobalHook` 当「镜腿按下」，确认靠 300ms 延迟 + 宿主补发的 `Enter` | 宿主不补发时单击仍能用（走 300ms 延迟确认），但**补发一旦迟到 >1.3 秒就会触发两次** | 看诊断行有没有出现 `按键 Enter` |
| **C1** | **两次镜腿点按之间要隔开 > 1.3 秒** | `cooldownMs=1000`（挂在延迟确认回调里：`t-y<1000` 就直接丢弃） | 冷却窗口内的第二次点按：**延迟确认被丢、补发 `Enter` 也被丢** ⇒ **这一下彻底没反应**（用户只会觉得「按了没反应」，然后更用力地再按） | 问完一宫后立刻再点一下，看有没有反应 |
| C2 | **单击**：宿主补发 `Enter` 必须在镜腿事件后 **1.3 秒内**到达 | `settleMs=300` + `cooldownMs=1000` | **一次单击触发两次动作**（问这一宫 ×2，第二次命中缓存会把解读重播一遍） | 单击 1 次，数盘面页诊断行的「按键」出现几次 `Enter`；再听 TTS 是不是念了两遍 |
| C2 | **双击**：两下镜腿的间隔 **< 300 毫秒** | `settleMs=300` | 第 1 下的「单击确认」先落地 → 用户**没想要却被问了这一宫**；随后双击在对话页变成「用建议语发问」→ **替用户把问题发了出去** | 连点两下（自己控制节奏，宁快勿慢），看是「切时间层」还是「先跳对话页 + 建议语自动发出」 |
| **C3** | **宿主必须为双击补发 `Backspace`**（没有它，「切时间层」这个功能**完全不存在**） | 双击靠第二下镜腿取消掉待确认，再由补发的 `Backspace` 转成 `DOUBLE` | 宿主不补发 `Backspace` ⇒ 两下镜腿被路由当成「第二下取消了第一下」⇒ **一个动作都不派发** ⇒ 用户永远切不了时间层 | 双击一次，看时间层有没有变 |
| C4 | **双击的补发**：宿主补发的 `Backspace` 必须在 **900 毫秒内**到达 | `doubleTapWindowMs=900` | 被当成**裸返回键** → **应用直接退出**（眼镜黑了） | 连点两下后如果界面突然黑掉/回到待机，就是踩到这条 |
| C5 | **滑动**：一次滑动的一对方向键（`Right`+`Down`）间隔 **< 200 毫秒** | `dirPairWindowMs=200` | 两个键都被当成独立动作 → **一次滑动连跳 2 宫** | 滑一次，看中宫焦点行的宫位跳了 1 档还是 2 档 |
| C6 | **滑动**：方向键必须在镜腿事件后 **300 毫秒内**到达 | `settleMs=300` | 镜腿的「单击确认」先落地 → **滑动顺带把当前这一宫问了** | 滑一次，如果滑动后立刻开始出解读/跳对话页，就是踩到这条 |

> **C0–C6 全部达标 ⇒ 交互链路在真机上成立。**
> 任何一条越界，**对应的就是商店审核里那句「无法切换 / 无法正常产生交互」的复现**。

## 2. 怎么判定（每条都要有证据，别靠感觉）

**证据 A：面板诊断行**（盘面页中宫）—— 显示最近一次按下的键值原文：
- 看到 `按键 GlobalHook` ⇒ 镜腿事件确实被投递了；
- 看到 `按键 ArrowRight` ⇒ 方向键到了；
- 看到 `按键 Enter` ⇒ 宿主补发确认到了；
- 看到 `按键 Backspace` ⇒ 宿主补发返回到了。

**证据 B：设备日志**（`[ziwei-agent] input ...` 行）—— 每一次按压都有：
```
[ziwei-agent] input down raw=GlobalHook action=temple → （吸收）
[ziwei-agent] input 延迟确认 → confirm          ← 300ms 后的单击确认
[ziwei-agent] input down raw=ArrowRight action=right → right
```
- 出现 `延迟确认 → confirm` = 单击被认成了**单击**；
- 出现 `→ double` = 被认成了**双击**；
- 出现 `→ （吸收）` = 这一下被契约层吃掉了（回声 / 配对键 / 冷却），
  **「按了没反应」和「被吞了」在界面上长得一样，只有日志能区分**。

**证据 C：界面结果** —— 切层看时间层标签、选宫看焦点行、退出看是否回到待机。

## 3. 建议的测法（每条 3 次，取最差的一次）

| 测法 | 次数 | 记录 |
|---|---|---|
| **单击** | 3 次，每次间隔 >2 秒 | 诊断行里 `Enter` 出现几次；是否念了两遍 |
| **双击（尽量快）** | 3 次 | 是否切了时间层（**不是**跳对话页 / 不是自动发问） |
| **双击（故意慢一点，约 0.5 秒）** | 1 次 | 用来**确认 C2 越界时的症状**（问这一宫 + 自动发问）—— 这一条是故意踩坑，看症状对不对得上 |
| **滑动** | 3 次 | 焦点行宫位跳几档；滑动后有没有莫名开始出解读 |
| **双击后立刻不动** | 1 次 | 应用有没有自己退出（**C3**） |

> 「故意踩坑」那一条很重要：它能证明**我们和真机的判断口径是一致的**，
> 也就是下次再遇到类似现象，能立刻对上号。

## 附：这轮本地已测出来的确定结论

### A. 时序契约扫描（真包 v1.0.20 的真代码，16 例 → 7 达标 / 9 破线）

| 用例 | 实际结果 |
|---|---|
| 单击（补发 Enter 600ms） | ✓ 问这一宫 ×1 |
| 单击（补发 Enter 1400ms） | ✗ **问这一宫 ×2**（C2 越界） |
| 单击（宿主不补发 Enter） | ✓ 问这一宫 ×1（走 300ms 延迟确认） |
| 双击（间隔 120ms / 250ms） | ✓ 切时间层 |
| 双击（间隔 320ms / 400ms） | ✗ **问这一宫 + 自动发起追问**（C6 越界） |
| 双击（宿主不补发 Backspace） | ✗ **一个动作都不派发** ⇒ 切时间层功能**完全不可用**（C3 越界） |
| 双击（补发 Backspace 迟到 1200ms） | ✗ **应用直接退出**（C4 越界） |
| 滑动（方向键配对 60ms） | ✓ 选宫 +1 档 |
| 滑动（方向键配对 300ms） | ✗ **选宫 +2 档**（C5 越界） |
| 滑动（方向键迟到 400ms） | ✗ **选宫 +1 档 + 顺带把这一宫问了**（C7 越界） |
| 连点两下（第二下距第一下 950ms） | ✗ 第二下**被冷却吞掉**（C1 越界） |
| 连点两下（第二下距第一下 1500ms） | ✓ 两次都生效 |
| 裸返回键 | ✓ 退出应用（设计如此） |

### B. 真包 + 真后端全链路（真 HTTPS，真端侧引擎，7 项断言全绿）

| 环节 | 实测 | 说明 |
|---|---|---|
| 端侧排盘 | **172ms** | 12 宫出全，运限层可用 |
| 问这一宫（真 `/api/agent/reading`） | **602ms ~ 1003ms** | 正文 **1486 字** / 屏显 **1464 字** / **38 个渲染行**（数据集原文，非模型生成） |
| 引文标注 | ✅ | `引文已降级（《天纪》原话以「引文略」代替）` |
| 正文纯文本化 | ✅ | 屏显里没有 `**` / `##` / 彩色 emoji 残留 |
| 追问（真 `/api/agent/ask`，无上文） | **10.7s ~ 20.9s** | 回答 **795 ~ 889 字** |
| 追问（带上文，请求体 ~1.1KB） | **11.1s ~ 29.2s** | 回答 **815 ~ 963 字** |
| 客户端超时余量 | ✅ | 实测最坏 29.2s vs 设定 120s（眼镜走蓝牙到手机，延迟会更差） |
