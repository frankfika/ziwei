## 1. 作品名称与一句话定位

### 1.1 名称

| | 中文名 | 英文名 |
|---|---|---|
| **主选** | 紫微星盘 | **Ziwei Star Chart** |
| 备选一 | 十二宫盘 | Twelve Palace Chart |
| 备选二 | 紫微十二宫 | Ziwei Twelve Palaces |

**主选理由**：

- 「紫微」是该传统术数的**专有体系名**（紫微斗数），不是形容词、不承诺结果，属于**学科/文化对象名**，与 Rokid《APP 内容体验规范》第 4.11 条列举的不收录名称（「六合」「心水」「白小姐」「曾道人」「铁算盘」「神算人」）在性质上不同——那批名称是**从业者人设包装**，而「紫微」是一个有典籍、有算法、有可复算规则的传统知识体系。
- 「星盘」把成品物化为**一张可读的盘面图**，而不是一次**结果性服务**。名字里没有任何承诺吉凶结果的词。
- 英文名 `Ziwei Star Chart` 直接音译专名 + 英文通用词，不含 `fortune` / `divination` / `astrology` / `horoscope`（英文语境下 `horoscope` 在部分平台审核里直接等同占星，风险更高）。

**备选一**用于「紫微」被判定不可用时的降级方案：完全绕开术数语汇，改成纯结构描述（十二宫），仍保留学科辨识度。

**不建议**的备选：「星盘」「命盘助手」这类泛称。Rokid 规范 4.25 条明确「应用名称属普遍性非专有名词」不收录，泛称反而增加被驳回概率。

### 1.2 一句话定位

> **说一句生辰，眼镜里立刻出现一张按传统规则算准的十二宫盘；抬头低头用准星点哪个宫，就听哪个宫的解读。盘面分本命、大限、流年、流月四层，上下键随时切换。**

英文（提审用）：

> Say your birth date and time. Your glasses compute a twelve-palace chart from deterministic traditional rules, then you look up and down to aim a cursor at a palace and hear its interpretation read aloud. The chart has four time layers — natal, decade, year and month — one keypress away.

### 1.3 分类建议

**作品分类：学习**（次选：娱乐）。

选「学习」而不是「生活」的理由：四类里只有「学习」在语义上把作品定位成**传统知识的结构化学习与研究工具**，而「生活」类里的命理类应用是最容易被理解为**结果性服务**的落位。作品的核心资产恰恰是「一套可复算、可复核的确定性计算 + 一份带出处标注的公开数据集」，把它放在「学习」下与产品实际形态一致。

## 3. 目标用户与真实使用场景

### 3.1 用户故事

**故事一 · 想弄懂自己盘面结构的人**
一位对紫微斗数有兴趣、但没有机会跟人当面讨论的用户，在通勤路上戴上眼镜。他想知道「我这张盘的官禄宫是什么结构」，但手机上的排盘 App 要他先解锁、再点选 5 个下拉、再等加载，30 秒里他已经把眼镜摘下来了。他的实际动作是：说出「1990年1月1日 子时 男」，然后**抬头看向盘面右上角那一格**，按确认键，听这一宫在讲什么。

**故事二 · 想听解读但不方便读字的人**
一位视力偏好听觉的用户（也是眼镜单色绿小屏的真实限制——一屏 480×352，13 维正文远超可读量）。他想知道「感情」这一维的传统解读文本。实际动作是：抬头把准星移到夫妻宫，按确认键，**耳朵收到解读正文**，眼睛全程不用读字。

**故事三 · 拿到书里一段断语想对照自己盘的人**
一位正在读传统命理书籍的用户，记住了一句断语（「天府管钱财」），想确认自己盘上是不是有天府、落哪一宫。实际动作是：说出生辰出盘，抬头扫一眼主星分布，**盯住选中格加粗描边的那一格**，三十秒内完成判断。

**故事四 · 复核者**
一位对「AI 说的靠不靠谱」有戒心的用户。他想确认盘面是算出来的还是编的。实际动作是：出盘后看中宫底部的「**端侧计算**」标记（中宫固定显示计算来源），并注意到解读文本里带出处标注而非无源生成。这是**本作品在合规上的核心差异点**，见第 9 节。

### 3.2 使用频次假设

低频但高意图。用户预期使用场景是「想认真看看自己命盘的时候」，不是日常陪伴型使用。对评奖标准里的「使用频率与传播性 10%」是**弱项**，靠的是「值得录一段短视频发出去」的传播性（见第 7 节），不是日活。

## 4. 核心体验流程

```
① 打开智能体
   └─ 若本机存过生辰 → 直接出盘；否则进入生辰输入浮层
        │
② 说出生辰（语音，唯一自然输入通道）
   └─ wx.speech.startRecognition → 解析「1990年1月1日 子时 男」
      ├─ 解析成功 → ③
      └─ 解析失败 → 提示换说法（不白屏、不抛技术错误）
        │
③ 出盘（端侧）
   └─ assets/engine.js 动态 import → chart(birth) → 十二宫 + 主星 + 四化
      ├─ 成功 → 中宫显示「端侧计算」+ 命宫自动选中
      └─ 端侧产物加载失败 → 静默回退服务端排盘 → 标记「服务端计算」
        │
④ 抬头选宫（IMU）
   └─ AbsoluteOrientationSensor → 四元数 → 相对基准姿态的 yaw(±22°)/pitch(±16°)
      → 映射到 4×4 盘面网格的准星 → 落格即选中（边缘 0.2 保护防抖）
      └─ 宿主未开启绝对方向能力 → 1.5 s 首帧超时 → 退 Accelerometer 倾斜通道
         （抬头/低头切宫，12° 阈值 / 5° 死区）→ 再不行 → 镜腿按键方向键
        │
⑤ 切时间层（上下键）
   └─ 本命 → 大限 → 流年 → 流月 → 本命 循环（算不出来的层自动跳过）
      → 端侧引擎 daXianLayer / liuNianLayer / liuYueLayer 算出运限四层
      → 盘面重画：四化换成带「限」/「流」前缀的那一套 + 运限宫名小标
      → 中宫换成「本层命宫落位」+「本层四化」，眼镜念出当前层名
      └─ 端侧引擎不可用（走了服务端兜底排盘）→ 运限层整体不可用，退回只有本命盘，
         上下键也随之退回「纵向选宫」
        │
⑥ 听解读（确认键）
   └─ 确认键（Enter）→ 先念宫名与主星 → 请求 /api/agent/reading 取 13 维原文
      → 取到该宫对应维度 → 全屏浮层显示 + TTS 朗读
      └─ 该宫无对应维度 → 退到「命格总览」维
        │
⑦ 追问
   └─ 解读浮层里再按确认键 → 追问浮层（4 条预设问题可用上下键循环，也可语音输入）
      → 焦点 = 宫位 + 时间层（问「今年」落到流年，问「大限」落到大限，没说跟当前层）
      → /api/agent/ask → 基于同一张盘的追问答案 → 显示 + 朗读
```

**按键映射（眼镜端没有 tap / 双击处理，之前的「单击…双击返回」是失效承诺，已改掉）**：

| 输入 | 做什么 |
|---|---|
| 准星（`AbsoluteOrientationSensor`） | **主交互**：二维指向选宫 |
| 抬头 / 低头（`Accelerometer`） | 兜底：俯仰角切宫（与左右键同向） |
| 左右键 | 沿**盘面外圈**巡宫，十二宫全覆盖 |
| 上下键 | 切换时间层；**唯一例外**——端侧引擎没加载（压根没有运限层）时退回纵向选宫 |
| 确认键（Enter） | 听当前宫解读 / 追问 |
| 返回键（Backspace） | 退出（浮层里是关闭浮层） |

> **左右键为什么走外圈**：四四方阵去掉中宫后，十二宫正好构成一圈 —— 从左上「巳」顺时针是「巳 午 未 申 酉 戌 亥 子 丑 寅 卯 辰」。网格横移够不到辰 / 卯 / 酉 / 戌（中宫挡在中间），而上下键已经让给「切时间层」，镜腿键就选不满十二宫 —— **眼镜没有触摸屏，模拟器里四向键是唯一的选择通道**，这一圈必须能走满。这一圈恰好就是**十二宫序**（命 → 兄弟 → 夫妻 → …），左右键巡宫等于按传统顺序走宫。

**关键设计约束**：任何一步失败都不白屏。生辰没听清 → 留在输入层并给提示；解读取不到 → 盘面照常显示，文字区写「这一段解读暂时取不到，盘面本身是端侧算的，不影响查看」；追问超时 → 写「追问暂时不可用，盘面和解读不受影响」；运限层算不出来 → 盘面照常显示本命盘，上下键自动改回选宫。

## 5. 眼镜原生性论证

比赛基础要求第 ③ 条为「**合理运用** IMU、TTS、导航、实时音视频等开放能力」。逐项对照：

### 5.1 IMU —— 已使用，且是产品的核心交互

这是本作品**不可替代**的眼镜原生部分：

| 项 | 实现 | 参数 |
|---|---|---|
| 绝对方向通道 | `AbsoluteOrientationSensor`（30 Hz）→ 四元数 → 相对基准姿态的 yaw/pitch | yaw ±22°、pitch ±16° 映射到 4×4 盘面 |
| 倾斜兜底通道 | `Accelerometer`（30 Hz）→ 静止基准重力向量 → 夹角累计 | 切宫阈值 12°、回中死区 5° |
| 镜腿按键兜底 | 左右键沿盘面外圈巡宫、上下键切时间层、Enter 确认、Backspace 返回 | 永远可用 |
| 边缘保护 | 准星压在格子边界 0.2 范围内不换宫 | 防边界抖动 |

**倾斜通道的四个参数只能在真机上确认一次**：`thresholdDeg: 12`（切宫倾角阈值）/ `rearmDeg: 5`（回中死区）/ `axis: 'x'`（俯仰轴）/ `signFlip: false`（方向开关）。眼镜戴在脸上的姿态决定「俯仰」对应设备坐标系的哪根轴，也决定抬头是下一宫还是上一宫 —— 低头没反应就把 `axis` 换成 `'y'` 或 `'z'`，方向反了就把 `signFlip` 改成 `true`（各改一行）。默认方向与左右键**同向**（都是地支 +1），两套通道不打架。

**为什么手机做不到 / 为什么眼镜才有意义**：十二宫是一张 4×4 的**空间化**盘面。在手机上，选宫就是点一个按钮；在眼镜上，盘面天然占据视野，用户用**视线方向**完成指向——这是「屏在哪里、手在哪里」之外第三条输入通道。AR1 + IMU + 30° FOV 的组合，让「抬头看哪一格」成为一个自然动作。

**已诚实标注的未验证项**：绝对方向传感器在真机上是否需要宿主显式 enable 能力 —— 代码里已经写了 1.5 s 首帧超时降级到加速度计通道，但**这条降级路径在真机上从未被触发验证过**（见第 10 节）。

### 5.2 TTS —— 已使用，且是主要的信息通道

`lib/tts.js` 实现了双通道（`wx.speech.playTTS` / `speechSynthesis.speak`），在以下节点播报：

- 切时间层 → 念出当前层名（「大限 32–41 岁」）
- 听解读 → 先念宫名与主星（「财帛宫，天府」；在运限层会先交代层名，四化统一念成「化禄 / 化权 / 化科 / 化忌」），再朗读整段解读正文
- 追问 → 朗读答案
- 浮层关闭 → 停止播报，避免叠声

**选宫本身不播报**：眼镜上用户靠盘面上加粗描边的那一格看选中态（中宫同步显示宫名），播报留给「切层」和「听解读」两个动作 —— 每换一格就播一次，准星扫过盘面时会很吵。

**为什么这是眼镜原生而不是「加了个朗读按钮」**：Rokid AI Glasses 的 HUD 是 480 × 352 单色绿屏，13 维解读正文动辄数千字，**视觉上根本读不完**。在这个约束下，「看得见盘面、听得懂解读」是唯一可行的信息分配方式——声音承担长文本，屏幕只承担结构与定位。这是硬件约束倒推出的产品形态，不是锦上添花。

### 5.3 导航 —— 明确不做，理由如下

比赛把「导航」列为开放能力之一，但本作品**主动不引入**：

1. **规避项冲突**。Rokid AI Glasses 的导航是官方功能。本作品一旦做「引导用户移动到某个宫位」，在体验和审核上都会向「官方导航」靠拢，触碰「不可以和官方功能高度相似」的规避项。
2. **交互已闭环，不需要**。准星本身就是绝对方向输入——用户已经在用头部指向，再叠一层「走到某处」的导航是重复的。
3. **30° FOV 下导航收益极低**。视野只有 30°，用户低头或转头就会丢失目标物，导航式引导的收益远小于直接指向。

**若后续要补，最小可行形态**是「相邻宫位之间的方向指引」（例如选中命宫后，轻声提示「事业在右前方」），而不是空间导航。但这是可选项，当前版本不做。

### 5.4 实时音视频 —— 明确不做，理由如下

1. **与隐私承诺冲突**。`AGENTS.md` 写明「不申请任何权限：不使用摄像头、麦克风采集、定位或系统媒体库」，且生辰、命盘、对话只存本机。引入实时音视频会推翻这条已写进智能体行为边界的承诺。
2. **产品不需要**。命盘是确定性计算的产物，**画面里没有需要识别的现实物体**。12 MP 摄像头对本作品零增益。
3. **硬件不划算**。2 GB RAM / 32 GB 存储 / 210 mAh 电池，跑实时音视频管线会让续航和稳定性为一项用不上的能力买单。
4. **审核加分有限**。基础要求是「合理运用」，不是「运用得越多越好」。**不堆砌能力反而是产品判断力的体现**——这条要在答辩时说清楚。

**结论**：本作品原生性落在 IMU + TTS 两项上，且这两项都是产品的**承重结构**，不是点缀。

## 6. 技术架构

三层结构，端侧优先：

## 7. 差异化亮点

（对应评奖标准「差异亮点 20%」）

### 7.1 四个硬差异

**① 盘面是「算」出来的，不是「生成」出来的。**
十二宫的宫位、安星、五行局、大限、流年、流月全部由固定规则计算得出，端侧 860 KB 引擎 0 网络延迟完成。智能体的行为边界里写死了「不允许自己推算星曜、编造落宫」。这与市面上绝大多数「问一句大模型就答一句」的作品有本质区别——**同一个生辰永远得到同一张盘，可复算、可复核**。

**② 解读是「查」出来的，不是「写」出来的。**
674,976 张命盘 × 13 维解读来自一份 CC BY 4.0 的公开数据集，出处与作者署名在应用内可见。文本带出处标注，不存在无源生成。这既构成合规护城河（见第 9 节），也直接回应 Rokid 规范第 8 条「恶意虚构事实、隐瞒真相以误导、欺骗他人」。

**③ 交互是「指向」，不是「点击」。**
头部绝对朝向 → 连续二维准星 → 落哪格选哪格。这是一个 30° FOV 单色绿屏上唯一说得通的选宫方式：**手机和网页都能做，但都不如在眼镜上自然**——因为盘面在你视野里，你不需要学习它在哪。镜腿按键是永远可用的兜底：左右键沿**盘面外圈**巡宫，十二宫全覆盖，这一圈恰好就是十二宫序（命 → 兄弟 → 夫妻 → …）。

**④ 盘面是「四层」的，不是「一张」的。**
本命之上叠大限 / 流年 / 流月三层运限，同样由端侧引擎的 `daXianLayer` / `liuNianLayer` / `liuYueLayer` 算出 —— 切层是**一次按键**，不是一次重排。而运限是**会变的**：大限 10 年一换、流年每年一换、流月每月一换。这给一个天然低频的作品提供了**站得住的复访理由**——「我现在走到哪一步」这件事每个月都有新答案。

### 7.2 与当前 AI 赛道榜上作品的区别

| 作品 | 核心 | 与本作品的区别 |
|---|---|---|
| 跑步大师 | 运动数据播报 | 领域无关；数据来自手表/App，非端侧计算 |
| 天球仪 | 天体位置与观测 | **交互范式同源**（看向哪选哪个），但对象是**外部世界实时位置**，依赖摄像头/定位与天文历算；本作品对象是**一张固定二维盘面**，纯 IMU + 确定性引擎，不依赖摄像头 |
| 地球仪 | 地球表面导航浏览 | 依赖外部地理数据与缩放手势；本作品数据量在服务端本地检索，眼镜端零数据下载 |
| 颈动书空 | 颈部动作切换内容 | 用的是**离散手势**（点一下头）；本作品是**连续空间指向**（准星落在哪格就是哪格），二维而非一维 |
| 虫洞穿越 | 游戏/沉浸体验 | 场景生成型，依赖实时音视频与渲染；本作品**刻意不用**实时音视频，210 mAh 电池下反而更稳 |

**一句话**：榜上多数作品把眼镜当**显示器**（把手机/PC 的内容搬到眼前），本作品把眼镜当**传感器**——用 IMU 把「看哪里」变成「选什么」。

### 7.3 传播性抓手

一个能录短视频的确定性瞬间：**戴上眼镜说出生辰，抬头扫过十二宫，准星每移一格，选中格就换一次加粗描边；按上下键切一层，盘面立刻重画成这一层的四化，眼镜念出层名。** 三十秒、单机、无需手机配对、无需网络（盘面部分）。这是「产品体验 20%」和「传播性 10%」的素材来源。

### 9.2 ⚠️ 数据集内含受限引文 —— 上架前必须处理（本次实测）

数据集的断语正文属 CC BY 4.0，但**正文中引用的倪海厦《天纪》原话不在该授权范围内**（CC BY-NC-SA 4.0，**不可商用**）。本次实测（2026-11-06，本机 `data/`，未联网）：

| 样本 | 含受限引文的维度文本 | 占比 | 命中数 |
|---|---|---|---|
| 1990 年前 200 盘（`citation:selftest`） | 2,069 / 2,600 段 | **79.6%** | 11,662 处 |
| 跨年份 200 盘（10 个年份 × 20 盘，1960–2024） | 2,168 / 2,600 段 | **83.4%** | 12,612 处 |

逐年密度 82.3%–84.6%，**无显著年份差异**。命中类型分布：`tianji-explicit` 8,965 处、`bracket-rule` 2,354 处、`tianji-locator` 1,256 处、`ni-label` 37 处。

**结论**：受限引文不是边角情况，而是**绝大多数解读都会碰到**。若上架时原样透出，等于在商业分发的场景里二次分发 NC 许可内容。

**处置（硬性）**：

1. `/api/agent/reading` 与 `/api/agent/ask` 的对外响应**必须在服务端做 `inline` 降级**（引文块替换为「（引文略）」），并在响应里带上当前降级模式标识；**不得**沿用 Web 端当前 `ZIWEI_CITATION_MODE` 默认 `full` 的行为（`apps/web/src/app/chart/page.tsx:173`）。
   → **✅ 已落实（2026-11-06）**，三层防线：
   - **输入层**：`apps/web/src/lib/agentCitation.ts` 的 `redactingService` 在**拼提示词之前**就把维度原文降级 —— 模型从没见过受限原文，复述无从谈起；
   - **输出层**：模型回答再跑一次 `redactCitations`（挡模型自带的《天纪》先验记忆）；
   - **提示词**：`AskService.extraSystem` 追加「只讲机制、不复述原话」的许可红线；
   - 模式解析用 `resolveAgentCitationMode`，**默认 `inline`**，只有显式 `ZIWEI_CITATION_MODE=full` 才放宽（与 Web 端默认 `full` 刻意不同，防止串改）；
   - 响应带 `citationMode` / `citationModeLabel`，眼镜端浮层**必须披露**当前模式。
   - 回归网：`tests/agent_citation.test.ts`（10 例），含「不降级时提示词里必有引文」的反证断言。
2. 实测 `inline` 降级后**无残留**《天纪》标记与定位符（`citation-guard` 自测对真实数据全量校验通过，25/25 用例通过；`tests/agent_citation.test.ts` 另对真实生辰断言降级后命中数为 0）。
3. 降级后正文可读性损失很小：本次 200 盘样本共移除 180,920 字，占 6,100,481 字的 **3.0%**。
4. 保留完整署名（CC BY 4.0 的义务），保留数据集自有的转述句（「倪师说……」这类是数据集自己的表述，属 CC BY 4.0 范围，不降级）。
