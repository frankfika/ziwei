## 1. 这个工程是什么

一个标准的 **AIUI 智能体工程**，跑在 Rokid AI Glasses 的 YodaOS 上。

- **单 Page 应用**：一个 `.ink` 文件同时承载配置、逻辑、结构、样式，没有多文件页面；
- **端侧优先**：十二宫的宫位、安星、五行局、大限、流年、流月全部由端侧引擎按固定规则算出，**不经过大模型**；
- **四层时间层**：本命盘之上叠大限 / 流年 / 流月三层运限，连点两下镜腿循环切换（见第 6 节）；
- **检索式解读**：解读正文来自公开的「紫微斗数开源解读数据集 v4.0-13d」（674,976 张命盘 × 13 维），服务端本地检索后返回，**不是模型生成的**；
- **眼镜原生交互**：绝对方向传感器（准星）为主，加速度计（抬头低头选宫）与镜腿手势为兜底；TTS 承担长文本朗读。

**三条不可破的边界**（已写进 `AGENTS.md`，改代码时别破坏）：

1. 排盘只走确定性引擎，智能体不得自行推算星曜；
2. 解读只从数据集原文检索，材料没收录就说「没收录」；
3. 不做人生决策建议：只讲盘面上客观存在的结构性事实。

## 2. 目录结构

```
apps/rokid-agent/
├── AGENTS.md                  # 智能体身份、系统提示词、能力边界、隐私口径（AIUI 会读它）
├── app.json                   # 页面声明、权限（仅 INTERNET）、窗口配置
├── app.js                     # 应用级生命周期：onLaunch / onShow / onHide / onError
├── package.json               # name: ziwei-chart-agent, version: 1.0.0
├── tsconfig.json              # 只覆盖 lib/ 与 types/（checkJs，用于 IDE 与类型检查）
├── .aixignore                 # AIX 打包排除项
├── pages/
│   └── index/
│       └── index.ink          # 唯一的 Page：<script def> + <script setup> + <page> + <style>
├── lib/                       # 纯 ESM 模块，1894 行，零第三方依赖
│   ├── chart-layout.js        # 十二宫网格布局 + 宫位↔维度映射（与 Web 端 GRID_POS 一致）
│   ├── head-cursor.js         # IMU：四元数 → 欧拉角 → 准星网格 → 地支；加速度计兜底
│   ├── time-layer.js          # 时间层（运限）：本命/大限/流年/流月四层的构建与焦点判定
│   ├── birth-parser.js        # 口语生辰 → 年/月/日/时辰/性别（纯函数；缺时辰落午时并标估算）
│   ├── chart-source.js        # 端侧引擎优先，失败静默落服务端
│   ├── api.js                 # wx.request 优先 / fetch 兜底，带超时
│   ├── tts.js                 # TTS 双通道（wx.speech / speechSynthesis）
│   ├── voice-input.js         # ASR 双通道（wx.speech / SpeechRecognition）
│   └── storage.js             # localStorage 命盘库（最多 20 张，只存本机）
├── types/
│   ├── runtime.d.ts           # AIUI 运行时类型（AbsoluteOrientationSensor 等）
│   └── wx.d.ts                # wx.* 风格 API 类型
├── assets/
│   └── engine.js              # 端侧排盘引擎（esbuild 产出的单文件 ESM，862.4 KB）
└── scripts/
    └── build-engine.mjs       # 打包 / 指纹核对脚本
```

**AIUI 标准项目结构对照**：官方样例为 `AGENTS.md / app.json / app.js / pages/ / widgets/ / workers/ / assets/`。本工程**没有 `widgets/` 和 `workers/`**——单页面、且 Agent Worker 不提供 `fetch`（网络请求必须由 Page 或 Widget 发起），因此所有网络调用都放在 Page 侧的 `lib/api.js` 里。

## 3. 端侧引擎：重新打包与指纹核对

### 3.1 为什么需要打包

AIUI 工程**不允许安装第三方 npm 包**，而排盘引擎依赖 `iztro` + `lunar-javascript`；眼镜端也没有 `tsx` / `node_modules`。所以引擎被打成**单文件 ESM**放进 `assets/engine.js`。

### 3.2 重新打包

```bash
# 在仓库根目录执行
node apps/rokid-agent/scripts/build-engine.mjs
```

输出示例：

```
✓ 已生成 apps/rokid-agent/assets/engine.js（862.4 KB）
  指纹 sha256:c28b129dd61858189f2937d0275e2cca1a5ccd03d5590d47ec30f150ece6aa67
```

打包参数（`BUILD_OPTIONS`，改动即改变指纹）：

```js
{ bundle: true, format: 'esm', platform: 'browser', target: 'es2020',
  minify: true, legalComments: 'none' }
```

产物 banner 里写着同一个指纹值：

```js
/*
 * 紫微星盘 · 端侧排盘引擎（自动生成，勿手改）
 * 来源：packages/chart-engine（vendored 自 https://github.com/Renhuai123/ziwei-doushu，MIT）
 * 生成：node apps/rokid-agent/scripts/build-engine.mjs
 * 指纹：sha256:c28b129d...
 * 署名义务见 ATTRIBUTION.md：数据集 CC BY 4.0 / 作者 王多鱼AI；引擎代码 MIT。
 */
```

### 3.3 核对指纹

```bash
node apps/rokid-agent/scripts/build-engine.mjs --check
```

- 打印**当前产物的实际指纹**（对 banner 之后的正文计算 sha256）；
- 与 banner 里写的值一致 → 产物没被动过；
- 与仓库记录不一致 → 说明产物过期或被手改，**重新打包**；
- 提审材料里应写上这个指纹，用来证明「真机跑的是哪一份产物」。

> 当前记录值（2026-11-06 实测）：
> `sha256:c28b129dd61858189f2937d0275e2cca1a5ccd03d5590d47ec30f150ece6aa67`，862.4 KB。

### 3.4 自动化背书：「打包不失真」

`scripts/build-engine.mjs` 与 `lib/chart-source.js` 的注释都提到 `tests/rokid_agent.test.ts` 会用 9 份金标准盘逐字段比对打包产物与源码引擎 —— **这个测试文件现在存在了**（2026-11-06 补上，64 例，已登记进 `tests/run.ts` 的 `SUITE_FILES`）。`tests/golden/` 下 9 份金标准盘是齐的（`1950-01-01-h00-male.json` … `2026-12-31-h11-female.json`）。**「打包不失真」现在有自动化测试背书**：打包产物与源码引擎的 `chart()` 输出整对象 `deepEqual`，未做任何归一化。

## 4. 在 AIUI Studio 里导入、打包、提审

### 4.1 导入工程

AIUI Studio 地址：**`https://aiui.rokid.com/`**（浏览器内运行，无需本地开发环境；用 Rokid 账号登录）。

顶部五个页签：**AIUI CODING / 代码 / 模拟调试 / 真机调试 / 提审**。

创建智能体有四种入口，**本工程走 GitHub 子目录导入**（2026-11-07 实测跑通）：

1. **GitHub 导入 —— URL 参数直导（推荐，可重复执行）**

   在地址栏打开（整段复制）：

   ```
   https://aiui.rokid.com/?import_from_github=https%3A%2F%2Fgithub.com%2Ffrankfika%2Fziwei%2Ftree%2Ffeat%2Frokid-spatial-joy-2026%2Fapps%2Frokid-agent
   ```

   页面加载即自动导入。`/tree/<ref>/<path>` 形式的地址会被识别成**子目录导入**；
   ref 支持分支与标签，且会**逐级回退**解析（先试整段、再逐段缩短），所以分支名里带斜杠（`feat/xxx`）也能命中。

2. **GitHub 导入 —— 表单路径**：「新建智能体 → GitHub 导入」，粘贴同一个 tree 地址。
   ⚠️ **表单的「确认导入」按钮点了不触发**（Vue `onSubmit` 未绑定上，无网络请求也无报错）—— 别在按钮上耗时间，直接用方式 1。

3. **本地导入（备用）**：「新建智能体 → 本地导入」，选 `apps/rokid-agent/`。
   它调的是 `window.showDirectoryPicker()`，弹出**操作系统原生目录选择器**，自动化点不了，只能人手动选。

4. **对话创建（AIUI CODING）** —— 不适用，本工程是手写的确定性代码，不交给 AI 生成。

> 本工程的工程骨架是手写的，**不需要** `npm create @yodaos-pkg/aiui-agent` 脚手架。
>
> 导入后第一件事：点顶部「**代码**」页签，确认文件树是 `AGENTS.md / app.json / app.js / pages/index/index.ink / lib/*.js / assets/engine.js`，且 `assets/engine.js` 不是 0 字节（`assets` 体积大，导入时留意有没有被截断）。

## 5. 真机调试要点与已知坑

### 5.1 已知坑（逐条）

| # | 现象 | 根因 | 规避 / 处置 |
|---|---|---|---|
| 1 | **镜腿上的按键不是标准键盘：`GlobalHook` 是设备专属键值** | 官方 AIUI 事件文档：Rokid Glasses 会额外上报一个 `GlobalHook` 键值，含义是「用户触摸到了镜腿按键」。它不是标准 Web 键值。真机实测（言值项目，已上架 Rokid 商店）：**滑动 = `GlobalHook` 先到、50~120 ms 后来一对方向键**；**单击 = `GlobalHook` 后 550~600 ms 补发 `Enter`**；**双击 = `GlobalHook`×2（约 200 ms 间隔）后补发 `Backspace`** | `lib/temple-input.js` 落地了完整契约：**① 认 `GlobalHook`**（不认它 = 镜腿点按彻底失灵）；**② 挂起 300 ms 判定滑动**，方向键到达即取消这次确认；**③ 确认冷却 1000 ms**，盖住补发的 `Enter`（否则「点一次跳两页」）；**④ 方向键按配对关系吸收**（一次滑动只走一档）；**⑤ 双击判别**（`GlobalHook`×2 → `Backspace` ⇒ 连点两下）；**⑥ 按下/抬起配对**，一次物理操作只执行一次；**⑦ 所有分支之前无条件 `preventDefault()`**，否则宿主的默认行为（Backspace 关应用 / 方向键滚根视图 / Enter 进导航模式）会把按键抢走 |
| 2 | **`fetch` 在真机跨域会卡住** | 眼镜上浏览器的跨域策略与手机直连不同 | `lib/api.js` 已改为 **`wx.request` 优先、`fetch` 兜底**；不要在别处直接用 `fetch` |
| 3 | **HTTPS 请求实际走蓝牙到手机 App** | 眼镜的网络链路经由手机 | 弱网表现与手机直连不同；所有请求都带超时（chart 8s / reading 10s / ask 40s），且失败一律走静默降级 |
| 4 | **Ink 模板对三元表达式支持差** | `.ink` 的模板表达式不是完整的 JS | 不要写 `{{a ? b : c}}`；当前用 `ink:if` 双层渲染规避（例如 `ink:if="{{readingLoading}}"` / `ink:if="{{!readingLoading}}"` 分两行） |
| 5 | **绝对方向传感器需宿主显式 enable 能力，否则要退回加速度计通道** | 宿主未开启能力时 `AbsoluteOrientationSensor` 不产生读数 | 代码里先建传感器并监听 `error`，同时设 **1.5 s 首帧超时**；拿不到首帧就 `fallbackToTilt()`，改用 `Accelerometer` 的「抬头低头选宫」通道，再不行退到镜腿滑动手势 |
| 6 | 加速度计的轴向与方向 | 眼镜戴在脸上的姿态决定「俯仰」对应设备坐标系的哪根轴，也决定抬头是下一宫还是上一宫 | `TILT_DEFAULTS`：`thresholdDeg: 12`（切宫倾角阈值）/ `rearmDeg: 5`（回中死区）/ `axis: 'x'` / `signFlip: false`。**这几个值只能在真机上确认一次**：低头没反应就把 `axis` 换成 `'y'` 或 `'z'`，方向反了就把 `signFlip` 改成 `true` |
| 7 | 准星边界抖动 | 准星压在格子边界上会来回跳 | `CURSOR_DEFAULTS.edgeGuard = 0.2`，准星离格子边缘 0.2 范围内不换宫 |
| 8 | 落进中宫时选择丢失 | 中宫（行 1–2 × 列 1–2）不是宫位 | `gridToBranch` 对中宫返回 `null`，此时**保持当前选中宫**，不丢选择 |
| 9 | TTS 叠声 | 没有可靠的播报完成回调 | `lib/tts.js` 用 `1200 + 文本长度 × 180 ms`（上限 15 s）估算时长做抑制；浮层关闭时 `stopSpeaking()` |
| 10 | Agent Worker 没有 `fetch` | AIUI 运行时的 Worker 环境不提供网络 API | 网络请求一律由 Page 侧发起（`lib/api.js` 在 Page 的 `<script setup>` 里被 import） |
| 11 | 动态 `import('wx')` 在部分环境不可用 | 运行时以 ESM 模块形式提供 `wx` | 所有 `wx.*` 调用都包在 `try { } catch { }` 里，失败落到 Web 风格分支；**永不让能力缺失变成白屏** |
| 12 | 运限层整体不可用 | 运限四层靠 `assets/engine.js` 的 `daXianLayer` / `liuNianLayer` / `liuYueLayer` 算；走服务端兜底排盘时引擎为 `null` | 界面退成只有本命盘，连点两下没有反应，不出现空白层 |
| 13 | 运限层里同一颗星挂两个四化标记 | 120 px 的格子塞不下两套标记，且单色绿 HUD 没有颜色可区分 | 运限层整层隐藏本命四化，只显示带「限」/「流」前缀的那一套；本命层照常显示本命四化 |
| 14 | 网格横移够不到四个宫 | 中宫（行 1–2 × 列 1–2）挡在盘面中间，辰 / 卯 / 酉 / 戌 走不到 | 选宫改走**盘面外圈**（`RING_ORDER`：巳 午 未 申 酉 戌 亥 子 丑 寅 卯 辰），十二宫全覆盖，且这一圈正好是十二宫序 |

### 5.2 调试时的优先级铁律

社区实战反复验证过的一条：**「不管在线接口成不成，页面永远必须有内容出，绝不白屏。」**

当前代码的四条兜底路径都实现了，但**没有一条在真机上被触发验证过**：

- 生辰没听清 → 留在输入层 + 提示换说法（不退出、不报错页）；
- 解读取不到 → 盘面照常显示，文字区写「这一段解读暂时取不到，盘面本身是端侧算的，不影响查看」；
- 追问超时 → 「追问暂时不可用，盘面和解读不受影响」；
- 运限层算不出来 → 盘面照常显示本命盘，连点两下没有反应，不出现空白层。

### 5.3 单色绿屏的设计约束

Rokid AI Glasses 的 HUD 是 **480 × 352 px、单色绿 Micro-LED、30° FOV**。

- 调色板只有三档：`#00ff66`（主）/ `#4da86c`（次）/ `#174526`（弱），没有彩色可用；
- 4 列 × 120 px，4 行 × 88 px，中宫 240 × 176 px；
- 13 维解读正文动辄数千字，**视觉上读不完** → 所以 TTS 不是附加项，是长文本的唯一可行通道；
- 不要设计需要彩色区分的图表，也不要在一屏里塞超过 12 个宫位的信息。

## 6. 时间层（运限）

盘面不是一张静止的图：**本命 → 大限 → 流年 → 流月**四层，连点两下镜腿循环切换。

**手势映射（当前唯一的真实交互）**：镜腿在真机上**只有手势，没有独立按键** —— 一次滑动发的是**一对**方向键，上下键从来不是独立手势。

| 手势 | 真机键值 | 做什么 |
|---|---|---|
| 准星（`AbsoluteOrientationSensor`） | — | **主交互**：抬头低头转头连续指向，二维选宫 |
| 抬头 / 低头（`Accelerometer`） | — | 兜底：俯仰角选宫（与镜腿滑动**同向**，都是地支 +1） |
| **镜腿前后滑动** | `ArrowRight`+`ArrowDown` / `ArrowLeft`+`ArrowUp` | 沿**盘面外圈**巡宫，十二宫全覆盖 |
| **轻点镜腿** | `GlobalHook` → 550~600ms 后补发 `Enter` | 听当前宫解读 / 追问 |
| **连点两下镜腿** | `GlobalHook`×2 → 补发 `Backspace` | 切换时间层（本命 → 大限 → 流年 → 流月 → 本命）。**唯一例外**：端侧引擎没加载（压根没有运限层）时没有反应 |
| **返回键** | 裸 `Backspace` | 退出 / 关闭浮层（盘面态是「重新说生辰」） |

> **为什么滑动走外圈而不是网格横移**：四四方阵去掉中宫后，十二宫正好构成一圈 —— 从左上「巳」顺时针是「巳 午 未 申 酉 戌 亥 子 丑 寅 卯 辰」。网格横移够不到辰 / 卯 / 酉 / 戌（中宫挡在中间），镜腿就选不满十二宫 —— 镜腿手势是唯一的选择通道，这一圈必须能走满。这一圈恰好就是**十二宫序**（命 → 兄弟 → 夫妻 → …），沿外圈滑动等于按传统顺序走宫。
>
> ⚠️ **上下键为什么不能承担独立动作**：真机一次滑动发**一对**方向键（前滑 `ArrowRight`+`ArrowDown`，后滑 `ArrowLeft`+`ArrowUp`），而且两个键的**到达顺序不保证**。所以「上下键切层、左右键选宫」那套旧映射在真机上等于**一次滑动同时触发「切宫 + 切层」两个动作域** —— 商店 v1.0.11 正是因为这个被审核驳回（焦点切换 / arrow 滑动事件 / 无法切换 / 无法正常产生交互）。现在四个方向键一律同义：滑动整条让给选宫，切层交给连点两下。

### 6.1 四层各是什么

| 层 | 盘面标题 | 这一层算什么 |
|---|---|---|
| 本命 | `本命盘` | 出生的那张盘（静态） |
| 大限 | `大限 32–41 岁` | 当前大限所在宫的十年盘：命宫随大限移位，四化按大限宫干推 |
| 流年 | `流年 丙午 2026` | 今年的盘：命宫在流年地支，四化按流年天干查表 |
| 流月 | `流月 九月 戊戌` | 当月的盘：「九月」是**当月农历月名**，干支按流月柱推 |

「今年」一律取**公历年**，与 Web 端同一口径。农历年要到正月初一才换，所以每年 1 月上旬到 2 月初，公历年的干支会比农历年「快」一步 —— 这是 Web 端已有的同一处取舍，眼镜端不另立一套（否则两边对不上）。

### 6.2 为什么做这一层

- **盘面本身是静态的**：排一次就固定，用户没有理由再来第二次；
- **运限是会变的**：大限 10 年一换、流年每年一换、流月每月一换；
- 所以「我现在走到哪一步」这件事每个月都有新答案 —— 这是**天然的复访理由**，也是「使用频率与传播性」这一项能拿分的前提。

### 6.3 怎么用

- **连点两下镜腿**：本命 → 大限 → 流年 → 流月 → 本命，循环（算不出来的层自动跳过；端侧引擎没加载时没有反应）；
- 切层时眼镜会**念出当前层名**（`大限 32–41 岁`），中宫同时换成「本层命宫落位」+「本层四化」两行；
- **追问带时间层焦点**：问题里说「今年」自动落到流年、说「大限」落到大限，没说就跟当前盘面停在哪一层（后端只认 `liunian` / `daxian` 两个白名单值）。

### 6.4 单色绿屏上的三处取舍

1. **运限四化带文字前缀**：大限用「限」（限禄 / 限权 / 限科 / 限忌），流年与流月用「流」（流禄 / 流权 / 流科 / 流忌）。单色绿 HUD 没有颜色可区分，只能靠文字前缀说清楚这是哪一层的四化。
2. **本命四化在运限层整层隐藏**：同一颗星挂两个标记会挤爆 120 px 的格子，且单色屏分不清哪个是本命的。本命四化在本命层照常显示；运限四化在中宫也列了一遍（「禄X　权Y　科Z　忌W」），两边都找得到。
3. **运限层的宫名小标用本命盘口径**：引擎有两套叫法（运限层原始叫「交友宫」），统一到「仆役宫」。不统一的话一格里会同时出现「仆役宫 交友宫」，用户会当成 bug。

> 解读正文仍来自**本命盘**的 13 维数据集（数据集没有运限版本），所以解读浮层会写明「本命X宫 · 维度 · 本层为Y宫」—— 同一地支在本命和本层不是同一个宫，不讲清楚就会讲错。

### 6.5 边界与降级

| 情况 | 表现 |
|---|---|
| 端侧引擎没加载（走了服务端兜底排盘） | 运限层**整体不可用**，界面退成只有本命盘；连点两下没有反应 |
| 某一层算不出来（如引擎没给出当前大限） | 自动跳过这一层，不让用户按到空白层 —— 空白层比「少一层」更糟 |
| 传感器完全不可用（既无准星也无抬头低头） | 连点两下**照常切层**；选宫改用镜腿滑动沿外圈巡宫（镜腿手势永远可用） |
| 追问时说了时间层 | 焦点带过去（`liunian` / `daxian`）；没说就跟当前层 |
