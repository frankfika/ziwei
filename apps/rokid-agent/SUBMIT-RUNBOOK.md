### ⚠️ 2026-11-11 真机交互链路修复（第十七轮 · Frank 报障触发）

**报障原文**：「焦点切换问题 arrow 滑动事件问题 无法切换 请检查 global hook 相关 无法正常产生交互」。

**根因不是猜的，是查出来的** —— 三条互相独立的证据链交叉验证：

| 证据 | 来源 | 结论 |
|---|---|---|
| `GlobalHook` 是 Rokid Glasses **专属键值**，含义是「用户触摸到了镜腿按键」 | 官方 AIUI 事件文档（Rokid Glasses 章节） | 镜腿**点按**走 `GlobalHook`，**不是** `Enter`。旧代码只认 `Arrow*`/`Enter`/`Backspace` ⇒ **点按确认彻底失灵** |
| 一次滑动 = **先发 `GlobalHook`，50~120 ms 后才发方向键** | FlexiLingo v0.5.74 真机实测 | 把 `GlobalHook` 当点按 ⇒ 一次滑动同时触发「移动 + 确认」 |
| `GlobalHook` **不携带可靠的「单击 / 滑动」分类**；宿主可能一次物理操作同时报 keydown 和 keyup | 词境项目真机结论 | 判定只能靠时序启发式；去重要用「按下/抬起配对」而不是固定时间窗口 |
| keyup 的宿主默认行为：`Backspace` 关应用 / `ArrowUp·Down` 滚根视图 / `Enter` 进导航模式 | 官方 AIUI 事件文档 | 页面**必须在所有分支之前**无条件 `preventDefault()` |
| **真机手势实测表**（言值项目 v0.x，已上架 Rokid 商店，2026-11 核对） | 言值项目真机实测 | **滑动** = `GlobalHook` → 50~120 ms 后来**一对**方向键（前滑 `ArrowRight`+`ArrowDown`，后滑 `ArrowLeft`+`ArrowUp`）；**单击** = `GlobalHook` → **550~600 ms** 后补发 `Enter`；**双击** = `GlobalHook`×2（约 200 ms 间隔）→ 补发 `Backspace` |
| Studio 模拟器的真实派发逻辑（bundle `PDt` / `h5`） | `https://static.rokidcdn.com/prod/rokid-aiuistudio/1.3.6/assets/index-D42SXuEj.js` | 模拟器也是「`GlobalHook` 先行，再按手势补 `Enter` / `Backspace` / `ArrowUp` / `ArrowDown`」，且**每个键都同时派发 keydown + keyup（间隔 1 ms）** |

⚠️ **旧文档的方向是反的**：此前把 `GlobalHook` 记成「滑动时的误报」，并用 `key-guard.js`（同码 150 ms 去抖）防它。
实际它**就是点按的载体**。旧防线已删除。

**已落地的修复**（`apps/rokid-agent/lib/temple-input.js` + `pages/index/index.ink`）：

1. **认 `GlobalHook`** —— 归一化层把它映射成「镜腿触摸」动作。
2. **挂起 300 ms 判定滑动** —— `GlobalHook` 到达先挂起，期间**方向键到达就取消这次确认**。
   取 300 是因为真机上「滑动 → 方向键」是 50~120 ms、「单击 → 补发 `Enter`」是 550~600 ms，300 刚好把两者分开。
3. **确认冷却 1000 ms** —— 盖住补发的 `Enter`（否则**点一下跳两页**）。
4. **方向键按配对关系吸收** —— 真机一次滑动发**一对**方向键，两个键必须只算一次方向；
   判据是**配对关系**（`Right`↔`Down` / `Left`↔`Up`）而不是时间窗，否则模拟器那种「一次滑动只发一个方向键」会把连续两次同向滑动吞掉。
5. **双击判别** —— `GlobalHook`×2 后补发的 `Backspace` ⇒ 「连点两下」；裸 `Backspace` ⇒ 物理返回键。
   ⚠️ 按下 / 抬起的配对必须挂在**原始的 `Backspace`** 上：否则双击的抬起会被判成「不是双击」⇒ 多执行一次返回（双击切层会顺手把浮层也关掉）。
6. **镜腿回声窗口 60 ms**（比方向键的 150 ms 抖动窗口窄）—— 否则间隔偏短的双击会被当成回声丢掉第一个。
7. **重复 `GlobalHook` 视为回声**抑制；**第二个 `GlobalHook` 取消挂起的单击判定**（真机双击不再误确认）。
8. **按下 / 抬起配对** —— 一次物理操作只执行一次（宿主只报 keyup、只报 keydown、两个都报，都正确）。
   ⚠️ `GlobalHook` 的**抬起绝不能取消挂起的单击判定**（模拟器 1 ms 内就派发 down+up，当成第二个 `GlobalHook` 会让点按永远不确认）。
9. **`event.code` / `event.key` / 数字 `keyCode` 三路兜底** —— 真机报哪个字段没有公开承诺，「认不出来」在眼镜上等于「这个键彻底失灵」。
10. **所有分支之前无条件 `preventDefault()`** —— 原来 `preventDefault()` 在函数末尾且三个浮层分支都提前 `return`，导致**在浮层按返回键 = 关浮层 + 退出应用**，**在浮层按确认键 = 同时进入宿主导航模式（此后方向键被导航层吃掉 → 滑动切不动宫）**。
11. **同时挂 `onKeyDown` 与 `onKeyUp`** —— 滑动是手势，可能只报 keydown；只挂 keyup 的页面在真机上「按了没反应」。
12. **录入浮层的返回键不再退出应用** —— 已有盘时返回 = 回盘面（取消这次重录），没有盘时才退出。
13. **长文本自己管滚动** —— `scroll-top` 绑定 + 方向键翻页（宿主的方向键默认只滚根视图，而根视图固定 480×352 滚不动）。
14. **中宫状态行实时显示最近一次输入的原始键值 + 控制台 `[ziwei-agent] input …` 日志** —— 上机第一分钟就能自证真机到底报什么（`DEVICE-CHECKLIST.md` §1.5 T2 从「待确认」变成「看一眼就知道」）。

**键位映射按真机手势重做（这一条才是驳回的主因）**：

旧映射「左右键选宫 / 上下键切层 / 确认键听解读」是**按键视角**的想象 —— 真机镜腿**没有独立的上下键**，
一次滑动发的是一对方向键，于是旧映射在真机上等于**一次滑动同时触发「切宫 + 切层」两个动作域**。

| 手势 | 真机键值 | 盘面态 | 解读浮层 | 追问浮层 |
|---|---|---|---|---|
| 镜腿前后滑动 | `ArrowRight`+`ArrowDown` / `ArrowLeft`+`ArrowUp` | 沿外圈选宫 | 翻解读原文 | 翻答案原文 |
| 轻点镜腿 | `GlobalHook` → 550~600 ms 后补发 `Enter` | 打开解读 | 打开追问 | 发送追问 |
| 连点两下镜腿 | `GlobalHook`×2 → 补发 `Backspace` | 切时间层 | 关闭浮层 | 换预设问题 |
| 返回键 | 裸 `Backspace` | 重新说生辰 | 关闭浮层 | 关闭浮层 |

四个方向键**一律同义**（`Left`/`Up` 上一档、`Right`/`Down` 下一档）—— 真机一次滑动里两个键的**到达顺序不保证**，
只有这样才与顺序无关。倾斜通道（加速度计）从「切层」改回「选宫」：它是准星不可用时的**兜底**，职责是替准星选宫。

#### 3.4 模拟器里出不了盘 —— **已定位、已修复、已在 Studio 复验通过**

页面原来在 `onLoad(query)` 里从 **query 参数** 取生辰，取不到才回落本地存档：

```js
const birth = this._resolveBirth(query);   // query.year/month/day/hour/gender
// 取不到才回落 latestProfile()（本地存档）
```

模拟器的「选择页面」下拉**只按页面名打开，不带 query**，右侧语音框是**只读回显**，
`AIUI CODING` 是**代码助手**（它不代调页面）—— 三条路都喂不进生辰，
所以页面永远停在输入浮层，**模拟器里出不了盘**。

```
对话流入参 → 本机存档 → 内置示例盘（1990-01-01 子时 男）
```

示例盘**不写入本机命盘库**，中宫标注「示例盘　返回键换成你的生辰」，
用户说出自己的生辰后立刻换成自己的盘。

语音失败一次，用户就被锁死在第一张盘上。现在返回键回到生辰录入浮层。
