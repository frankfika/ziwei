# 报名用作品策划案

报名时上传的「作品策划案」PDF 放在这里。

## 生成

```bash
npm run proposal:pdf
```

产物：`紫微星盘-作品策划案.pdf`（A4，封面 + 目录 + 正文，当前 17 页 / 约 5.2 MB）。

## 三条硬约束（脚本会自动保证，违反就构建失败）

1. **红线词不得出现在对外 PDF 里。** `PROPOSAL.md` §9.3 的完整禁用词表**只存在于内部文档**；
   生成脚本会把该块替换成占位说明。上报材料里逐条列出红线词，等于自己把红线词摆在审核面前。
2. **脱敏后的正文仍含红线词 → 拒绝对外产出。** 脱敏文案本身也可能带进红线词
   （第一版就写了「准确率 / 命中率 / 算命」，结果占位说明把红线词又带回了 PDF）。
   这条自检是硬失败，不是告警。
3. **体积 ≤ 30 MB、文件名 ≤ 50 字符。** 报名表单对这两项有硬限制，超了直接被拒。

## 为什么 PDF 不进 git

它是**生成物**，随 `PROPOSAL.md` 每改一次就变一次；入库会让 git 历史反复存几 MB 几乎相同的大文件
（与 `/data/` 同理，见根目录 `.gitignore`）。需要提交物时跑一次上面的命令即可。

`npm test` 里有一条用例会**现生成现校验**（体积 + 红线词），所以 fresh clone 也能验证这条链路是通的。
