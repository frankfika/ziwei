# 键口径与排盘语义（KEY_SEMANTICS）

> 这份文档记录**实测确认**的口径，不是照抄上游 README。
> 所有结论都有对应可复现的测试。

---

## 1. 一句话

**数据集 key 的 `y/m/d/h` 就是 `generateChart()` 的输入，零折算。**

```
key = "1990-01-01-0-male"
      ↑    ↑    ↑ ↑   ↑
      年  月  日 时辰 性别
              序号 0–11
```

---

## 2. 实测过程

### 2.1 方法

数据集每条记录自带一个 `ms` 字段 —— **命宫第一颗主星**（如 `"天府"`），
命宫无主星时为 `null`。这是一个天然的**盘面指纹**。

对样本 key 同时跑三种口径，比较引擎算出的命宫第一主星与数据集 `ms`：

| 口径 | 含义 | 匹配率 |
|---|---|---|
| **A 直排** | `chart({year:y, month:m, day:d, hour:h, gender:g})` | **360 / 360 = 100%** |
| B 次日折算 | 日期 +1、时辰归 0（晚子时折进排盘日） | 0 / 360 = 0% |
| C 真太阳时校正 | 按经度校正时辰后再排 | 未作为独立口径测试（口径 A 已 100%，无需再试） |

### 2.2 结论

- 口径 A **100% 命中** → 数据集是**直接以 (日期, 时辰序号) 排盘**生成的
- 口径 B **0% 命中** → 数据集**没有**把晚子时折算进 key
- 因此：**不做真太阳时校正，不做子时换日折算**，检索键即引擎入参

### 2.3 复现

```bash
npm run index:build -- --years 1990,2000,2020
npx tsx tests/test_key_alignment.ts
```

测试文件：`tests/test_key_alignment.ts`（由 tests agent 扩充）

## 3. 时辰序号 ↔ 钟点

| 序号 | 地支 | 钟点区间 | 序号 | 地支 | 钟点区间 |
|---|---|---|---|---|---|
| 0 | 子 | 23:00–00:59 | 6 | 午 | 11:00–12:59 |
| 1 | 丑 | 01:00–02:59 | 7 | 未 | 13:00–14:59 |
| 2 | 寅 | 03:00–04:59 | 8 | 申 | 15:00–16:59 |
| 3 | 卯 | 05:00–08:59 → 实际 05:00–06:59 | 9 | 酉 | 17:00–18:59 |
| 4 | 辰 | 07:00–08:59 | 10 | 戌 | 19:00–20:59 |
| 5 | 巳 | 09:00–10:59 | 11 | 亥 | 21:00–22:59 |

> ⚠️ **时辰序号不是 0–23 点钟。** `hour=0` 是子时（23:00–00:59），
> 不是「0 点」。上游 v3.0 数据集曾有 `h11` 被误读成「上午 11 点」的坑，
> 这里显式澄清。

子时横跨两段：
- **早子时** 00:00–00:59 → 排盘日 = 当日
- **晚子时** 23:00–23:59 → 排盘日 = **次日**（倪海厦体系 / 三合派标准）

## 4. 用户输入钟点怎么办

产品接受两种输入，**但只在输入层做转换，引擎与数据集口径不变**：

```
用户输入钟点 23:30
      ↓  resolveChartDate()  ← 唯一的转换点
排盘日 = 1990-01-02，时辰序号 = 0
      ↓
chart({year:1990, month:1, day:2, hour:0})   ← 引擎入参，与数据集同口径
      ↓
查 key "1990-01-02-0-male"                    ← 直查，无折算
```

实现见 `packages/chart-engine/src/index.ts` 的 `resolveChartDate()`。

**不做真太阳时校正** —— 数据集没做，做了 key 就会错位。
真太阳时/夏令时的对齐是 MVP 之后的独立需求（见实施简报第 10 节）。

## 5. 数据集覆盖范围

| 项 | 值 |
|---|---|
| 年份 | 1950–2026（77 年） |
| 每张盘 | 真实存在的公历日期 × 12 时辰 × 2 性别 |
| 总盘数 | 674,976 |
| 每盘字数 | 约 3.0 万字（13 维合计） |
| 覆盖键数 | 1950–2026 内所有 `(日期, 时辰, 性别)` 组合 |

**注意**：数据集只含**真实存在的日期**（无 2 月 30 日、非闰年 2 月 29 日）。
引擎也会对非法日期抛 `RangeError` —— 两侧一致。

## 6. 未覆盖时必须诚实

当 `reading()` 返回 `status: 'not-covered'`：

- **必须**把 `message` 原样展示给用户
- **不得**用模型生成的内容填补
- **不得**静默降级成"暂无解读"而不说明原因

两种未覆盖原因：
- `year-not-indexed` —— 该年份还没解压/建索引（可补数据解决）
- `key-not-found` —— 该年份已索引，但没有这一条（通常超出数据集覆盖范围）

## 7. 排盘口径的其它分歧点

引擎本身在某些流派分歧处有选项，MVP 取值如下：

| 分歧点 | MVP 取值 | 位置 |
|---|---|---|
| 闰月归属 | `split`（月中分界，主流口径） | `DEFAULT_LEAP_MONTH` in `engine/school-config.ts` |
| 亮度表 | 全书派（SB 表） | `setBrightnessSchool()` |
| 子时换日 | 晚子时按次日 | `resolveChartDate()` |

这些是**引擎内部**的口径，与数据集生成时一致（已由 360/360 校验背书）。
若未来要切流派，需**同步重新生成数据���**或只用于展示层。
